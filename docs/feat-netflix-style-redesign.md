# feat/netflix-style-redesign — 넷플릭스식 카드 UI 개편

## 문제 상황

지금 홈은 **세로 목록 하나**다. '오늘의 메뉴' 아래로 최근 조리 3개, 즐겨찾기 3개, 그리고 전체 레시피 1,150개가 전부 같은 모양의 타일로 세로로 쌓인다. 결과가

- **한 화면에 3~4개밖에 안 들어온다.** 1,150개를 세로 타일로 훑으려면 300번 넘게 스크롤해야 한다.
- **사진이 작다.** 레시피를 고르는 근거는 사진인데, 타일에서는 68×68 썸네일이다.
- **위계가 없다.** '최근 조리'와 '전체 레시피'가 같은 비중으로 보인다.

크림색 바탕(`#FAF5EE`)도 사진과 싸운다. 음식 사진은 대부분 따뜻한 색이라 크림 바탕에서 경계가 흐려진다.

## 검토한 대안

**세로 목록을 유지하고 사진만 키울지** 고민했다. 카드를 키우면 한 화면에 2개만 들어와 더 나빠진다. 카탈로그가 1,150개인데 세로 스크롤 하나로는 어떤 크기를 골라도 답이 없다.

**가로 열(rail)** 로 가면 한 줄에 3.5개가 보이고 줄마다 다른 기준을 줄 수 있다 — 넷플릭스가 수만 편을 이 구조로 다룬다. 세로 스크롤은 '어떤 종류를 볼지', 가로 스크롤은 '그 안에서 무엇을' 을 담당해 축이 분리된다.

## 최종 결정

**1. 바탕을 흰색으로.** 사진을 카드로 늘어놓는 화면에서는 바탕에 색이 있으면 음식 사진의 색과 싸운다. 중성색은 아주 살짝 차갑게(`#F4F4F6`) 잡았다 — 크림 계열을 남기면 흰 바탕이 탁해 보인다.

**2. 포인트 주황을 한 단계 밝게.** 흰 바탕에서는 같은 주황도 세게 보이므로 `#D4572E` → `#FF5A1F`. 기존 색은 `accentDeep` 으로 남겨 그라데이션과 눌림 상태에 쓴다 — 브랜드 색이 끊기지 않게.

**3. 카드는 3:4.** 영화 포스터는 2:3 이 표준이지만 **음식 사진은 가로가 표준**이라, 그대로 세로로 길게 자르면 음식이 잘린다.

**4. 조리 화면도 흰 바탕을 쓴다.** 어두운 조리 모드를 만들어 실기기로 확인해 봤지만 되돌렸다. 조리대에서 팔 길이 밖으로 보는 화면이라 대비를 올릴 이유는 분명했는데, **앱 안에 밝기가 다른 섬이 하나 생기는 대가가 더 컸다.** 화면 하나만 색 체계가 달라지면 그 화면에 얹히는 모든 위젯이 두 벌의 색을 갖게 되고(실제로 `InfoStrip`·`FoodImage` 가 밝은 판으로 남았다), 새 위젯을 만들 때마다 같은 실수를 반복하게 된다.

대신 **구조로 거리를 벌었다.**

- 단계 안내를 23 → 25px 로 키우고, 진행바를 **단계 수만큼 나눈 칸**으로 바꿨다. 채워진 길이보다 "몇 칸 남았나"가 빨리 읽힌다.
- **타이머가 없는 단계에서는 시계와 조작 버튼을 통째로 감춘다.** `00:00` 과 비활성 버튼이 화면 한가운데를 차지하면 정작 읽어야 할 안내가 아래로 밀린다. 대신 `이 단계는 타이머 없음` 한 줄만 남긴다.
- **조리 중에는 단계 사진을 띄우지 않는다.** 읽어야 할 안내가 화면 위쪽에 와야 한다. (덧붙여 지금 시드 데이터의 단계 사진은 **전부 403** 이라 자리표시자만 크게 남는다 — 아래 참고)
- **이전 · 질문하기 · 다음 단계를 하단 고정 바로 모았다.** 손이 젖은 채로 누르는 화면이라 세 동작이 스크롤 밖에 있어야 한다. 전에는 '이전 단계'가 앱바에, '직접 입력'이 본문에 흩어져 있었고 본문 버튼은 하단 버튼에 가려지기까지 했다.

어두운 조리 모드는 앱 전체 다크 모드를 넣을 때 그 체계 안에서 다시 보는 게 맞다.

**5. 후기 화면 상단을 주황으로 채운다.** 조리를 마치고 넘어왔다는 신호를 색으로 준다 — 조리 화면과 후기 화면은 구조가 비슷해서, 헤더 색이 아니면 단계가 바뀐 걸 알기 어렵다.

**6. 계정을 하단 탭으로.** 홈 우상단 아바타의 계정 시트를 `AccountScreen` 으로 끌어올렸다. 시트는 로그인/로그아웃 하나만 담기에도 빠듯했는데 #59 가 프로필 설정을 붙이며 이미 좁아졌다. 빈 자리는 검색 아이콘이 받는다.

**7. 게스트 분기는 열 단위로 껐다 켠다.** #59 가 넣은 "게스트에게는 개인화 열 대신 로그인 안내" 규칙을 그대로 지킨다. 오히려 가로 열 구조가 이걸 더 깔끔하게 담는다 — 열 하나를 통째로 안내 카드로 갈아 끼우면 된다. **빈 가로 열은 고장으로 보이므로** 데이터가 없는 열은 아예 그리지 않는다.

## 검증

- 전체 **422개 통과**, `flutter analyze` 무경고 (#59 머지 뒤 리베이스 완료)
- 화면 구조만 바꾸고 **동작·API 호출·상태 관리는 건드리지 않았다.** 조리 흐름 테스트 10건, 검색 테스트 2건이 그 증거다(문구·레이아웃이 바뀌었는데 통과한다)
- 그리드에서 카드 폭이 무한으로 들어와 높이 계산이 터지는 문제를 `AspectRatio` 로 잡았다(테스트가 잡아 줬다)
- **에뮬레이터에서 AWS 서버(13.209.243.235)에 붙여 홈 → 검색 → 상세 → 조리 → 후기까지 실제로 눌러 확인했다.** 테스트가 못 잡은 두 가지를 여기서 발견했다:
  - 조리 화면을 어둡게 만들었더니 **타이머 카드가 흰 바탕에 흰 글씨**가 됐다. `AppColors.ink` 는 밝은 테마에서 글자색이지만 그 자리에서는 **어두운 판의 배경색**이었다 — 이름만 보고 치환하면 안 되는 종류다.
  - `InfoStrip`·`FoodImage` 도 색을 고정하고 있어 밝은 판으로 남았다. 이 두 가지가 어두운 모드를 되돌린 직접적인 이유다.
  - 되돌린 뒤에는 타이머 카드가 **검은 판에 안 보이는 버튼**이 됐다(원래 진한 갈색 판이었는데 `ink` 를 더 어둡게 바꿔 대비가 무너졌다). 흰 카드 + 테두리로 바꿨다.
- #59(게스트 우선)와 `main_shell.dart` 에서 6군데 충돌했고 전부 **양쪽을 살리는 쪽으로** 풀었다. 게스트 안내 카드·세션 갱신·프로필 온보딩 자동 표시는 그대로 살아 있다

**8. 어디서든 로고를 누르면 홈으로.** 넷플릭스 좌상단 로고와 같은 자리, 같은 뜻이다. 레시피 상세 → 조리 설정으로 깊어져도 한 번에 처음으로 돌아온다.

**루트로 돌아가는 것만으로는 부족하다** — 검색 탭에서 상세로 들어갔다면 `popUntil` 뒤에도 '검색 탭의 루트'에 남는다. 그래서 탭 상태를 셸 밖(`shell_tab.dart`)으로 뺐다. 누른 위젯은 그 시점에 이미 사라져 셸의 State 를 찾을 수 없기 때문이다.

**조리 화면에는 붙이지 않았다.** 진행 중인 세션을 실수로 날릴 수 있어, 그 화면은 X 버튼이 확인을 거쳐 닫는다.

**9. 좌우로 밀어 단계를 넘긴다.** 손에 재료가 묻은 채로 작은 버튼을 겨냥하는 것보다 화면 아무 데나 밀어내는 편이 쉽다. 가로 제스처만 보므로 세로 스크롤과 겹치지 않는다.

**마지막 단계에서 왼쪽으로 미는 것은 무시한다.** 조리 완료는 되돌리기 어려운 동작이라 스친 제스처로 끝나면 안 된다 — 완료는 버튼으로만 한다. 속도 임계값(200)도 둬서 스크롤하다 손가락이 비스듬히 나가는 것을 걸러낸다.

**10. 레시피 분류를 칩으로 띄운다.** 상세 화면 설명에 `조리방법: 굽기 | 요리종류: 반찬` 이 **본문 텍스트로 섞여 있었다.** 1,150건 중 1,142건이 같은 형식이라 이걸 뽑아 칩으로 올렸다(`RecipeTags`).

**`해시태그:` 줄은 칩에 넣지 않는다.** 이름과 달리 내용이 **주재료**다(가슴살·등심·저염간장…). 154종 전부 재료명이고 용도 태그는 하나도 없다. 분류 칩과 나란히 두면 '저염간장'이라는 카테고리가 있는 것처럼 읽히는데, 사전에 그런 태그가 없어 눌러도 걸릴 필터가 없다. 값 자체는 재료 목록에 이미 나온다(표본 12건 중 11건).

영양 줄도 본문에서 뺐다 — 상세에 스탯 타일이 따로 있다.

**이건 임시다.** 백엔드에 태그 테이블(`tags`/`recipe_tags`, 4축 25개)이 이미 있고, 레시피에 태그가 붙고 API 가 생기면 **이 파싱을 지우고 그쪽을 쓴다.** 파일 맨 위에 그렇게 적어 뒀다.

**11. cooklog 브랜드 적용.**

- **심볼(냄비와 김)은 이미지가 아니라 직접 그린다.** 김 세 줄을 따로 움직여야 로딩 표시로 쓸 수 있고, 어떤 크기에서도 깨지지 않는다. 좌표는 원본 SVG 의 64×64 뷰박스를 그대로 쓰고 캔버스에서 배율만 맞춘다(`CookLogMark`).
- **워드마크는 이미지를 쓴다.** 글자 모양 자체가 브랜드라 텍스트로 흉내 내지 않는다. 로그인 화면에만 들어간다.
- **심볼은 모든 화면 상단 왼쪽에 있고 누르면 홈으로 간다.** 넷플릭스와 같은 자리, 같은 뜻이다. 뒤로가기가 있는 화면에서는 그 옆에 붙는다.
- **로딩은 빙글빙글 도는 원 대신 김이 오르는 냄비다**(`CookLogLoader`). 기다리는 동안에도 브랜드가 보이고, "끓고 있다"가 이 앱에서 기다림의 은유로 맞는다.

  김이 **완전히 꺼지지는 않게**(하한 0.3) 했다. 처음에는 세 줄을 차례로 쌓았다가 리셋하는 방식이었는데, **한 번이라도 비는 순간 냄비만 남아 로고가 아닌 다른 것으로 보였다** — 에뮬레이터에서 그 프레임을 잡아 고쳤다. 지금은 아래 줄부터 차례로 밝아지는 파도다.

  모션을 끈 사용자에게는 **티커를 아예 돌리지 않는다**. 처음에는 `build` 에서만 분기했는데, 보이지도 않는 애니메이션이 계속 프레임을 먹었다 — 테스트가 잡아 줬다.

**12. 태그 열을 권유 문장으로 띄운다.**

홈에 `한식`·`안주` 를 그대로 붙이면 **목록의 이름표**가 되지만 **권유**가 되지는 않는다.
넷플릭스가 "지금 뜨는 콘텐츠"라고 쓰지 "인기"라고만 쓰지 않는 것과 같다.

```
중식이 당기는 날              중식
집에서 만드는 양식            양식
출출할 때 딱                 간식
```

태그마다 문장을 2~3개 두고 그릴 때 하나를 고른다(`TagInvitations`). **사전 24개 중 매번 12개를
무작위로 뽑으므로 홈을 열 때마다 구성이 달라진다** — 카탈로그가 1,150건으로 고정돼 있어도
매번 다른 요리가 눈에 들어온다. 태그 이름은 열 오른쪽에 작게 붙여 무엇으로 묶였는지 남긴다.

전부(24개) 띄우지 않는 이유는 스크롤이 지나치게 길어지고 요청도 그만큼 늘기 때문이다.
서넛만 띄우면 반대로 카탈로그가 작아 보인다.

**순차로 부르지 않는다.** 12번을 한 번씩 기다리면 홈이 그만큼 늦게 뜬다. 다만 한꺼번에
던지지도 않는다 — 서버가 EC2 한 대라 6개씩 묶어 보낸다.

**상단 헤더는 워드마크만 남겼다.** '셰프님 👋' 인사말과 시간대별 문구를 걷어냈다.
검색 아이콘도 뺐다 — 하단 탭에 검색이 있는데 같은 화면에 두 입구를 두면 어느 쪽이
무엇인지 설명해야 한다.

**빈 태그는 건너뛴다.** `아이반찬`·`초스피드`·`혼밥` 은 부여가 0건이라(백엔드 #90 참고)
뽑히더라도 결과가 비면 그 열을 그리지 않는다.

**태그를 못 불러와도 홈은 그대로 뜬다.** 태그 열은 있으면 좋은 것이지 없으면 못 쓰는 화면이
아니다 — 레시피 목록·최근 조리는 영향받지 않는다.

**13. 상단 태그 칩.** 사전 24개를 전부 넣는다. 몇 개만 고르면 "왜 이것만 있나"를 설명해야 한다.
누르면 그 태그의 레시피를 격자로 보여주고, `전체` 로 돌아온다.

**칩에서는 열을 쓰지 않고 격자를 쓴다.** 한 태그를 고른 사람은 이미 무엇을 볼지 정했으므로
가로로 밀어 가며 훑을 이유가 없다. 세로 격자가 한 번에 더 많이 보여 준다.

**14. 오늘의 추천을 무작위로 고른다.** 목록의 첫 건으로 고정돼 있어 1,150건이 있어도
홈을 열 때마다 같은 요리(`LA 갈비구이`)가 나왔다.

**단계 사진이 전부 403 입니다.** `GET /recipes/{id}` 가 내려주는 `steps[].imageUrl` 이

```
https://cookpilot-photos-….s3.ap-northeast-2.amazonaws.com/review-photos/….jpg
→ HTTP 403
```

두 가지가 겹쳐 있다.

1. **경로가 `review-photos/` 다.** 레시피 단계 사진인데 후기 사진 접두사를 쓰고 있다. 시드에 잘못 들어간 것으로 보인다.
2. **객체가 공개되어 있지 않다.** 버킷의 공개 읽기는 접두사 단위로 걸려 있는데 이 객체들은 걸리지 않았다.

앱에서는 조리 화면에서 사진을 걷어냈으니 당장 드러나진 않지만, **레시피 상세의 단계 사진도 같은 URL 을 쓴다.** 백엔드 쪽에서 봐야 한다.

## 이 PR 에 없는 것

**1. 상단 카테고리 칩(파티 · 자취방 · 술안주 · 카테고리).** 시안의 핵심인데 **넣지 않았다.** 백엔드에 태그 사전(문화권·음식형태·조리법·용도 25개)은 있지만 **레시피에 붙은 태그가 0건이고 태그로 거르는 API 도 없다.** 칩을 지금 넣으면 눌러도 빈 화면이 나온다.

**2. 유튜브 가져오기 탭.** 추출 기능은 `web` 저장소에만 있다. 앱에 넣으려면 추출 API 를 백엔드로 옮기거나 앱이 웹 API 를 직접 부르는 구조를 정해야 한다 — 디자인 개편이 아니라 새 기능이다.

**3. 다크 모드 설정.** 조리 화면은 항상 어둡게 했지만, 앱 전체를 어둡게 하는 설정은 넣지 않았다. 전 화면 색 토큰을 테마로 빼는 별도 작업이 필요하다.

## 이후 작업에서 지킬 것

- **색 토큰을 이름만 보고 치환하지 말 것.** `ink` 는 밝은 테마에서 글자색이지만 어두운 판의 배경색으로도 쓰인다. **위젯 테스트는 색을 검증하지 않으므로 422개가 다 통과해도 남는다** — 실기기로 눈으로 봐야 잡힌다.
- **화면 하나만 다른 색 체계를 주려면 그 대가를 먼저 계산할 것.** 공용 위젯이 전부 두 벌의 색을 갖게 된다. 어두운 조리 모드를 되돌린 이유가 이것이다.
- **`RecipePosterCard` 에 폭을 곱해 높이를 만들지 말 것.** 그리드에서 폭이 무한으로 온다. `AspectRatio` 를 쓴다.
- **`showAccountSheet` 는 이제 아무도 호출하지 않는다.** 지우지 않았다 — PR #60(회원 탈퇴)이 그 함수를 확장하고 있다. #60 은 `AccountScreen` 으로 옮기는 게 맞다.
- **사진 리사이즈가 이 디자인의 전제다.** 카드 UI 는 사진이 전부인데 카탈로그 1,142건이 식약처 원본(장당 600KB+)을 가리킨다. `FoodImage` 의 `cacheWidth` 가 디코딩은 막지만 **다운로드 용량은 그대로**라, 썸네일 없이는 카드 격자에서 체감이 나쁘다.

# 2차 — 시안에 맞춰 다시 맞춘 홈·기록, 그리고 iOS 실기기

## 히어로가 글자를 겹쳐 그리던 버그

실기기에서 히어로의 눈썹·제목·메타가 한자리에 겹쳐 그려졌다. 원인은 레이아웃 예외였다.

```
BoxConstraints forces an infinite width.
  BoxConstraints(w=Infinity, 56.0<=h<=Infinity)
  FilledButton-[<'home-hero-start'>] ← Row ← Column ← Positioned ← Stack
```

테마가 모든 버튼에 `minimumSize: Size.fromHeight(56)` 을 건다. 이건 **폭이 무한**이라는 뜻이고,
세로로 꽉 채우는 버튼에는 맞지만 `Row` 안에 늘어놓으면 터진다. 레이아웃이 실패하면 자식이
배치되지 않아 전부 원점에 그려진다 — 그게 "글자가 겹친다" 의 정체였다.

히어로 버튼에만 `minimumSize: Size(0, 44)` 를 줘서 고쳤다.

**처음에 재현하지 못한 이유**: 히어로만 따로 띄운 테스트에 `buildCookPilotTheme()` 을 씌우지
않았다. 기본 테마에는 저 `minimumSize` 가 없어서 통과했다. `home_hero_test.dart` 는 이제 앱
테마를 쓴다.

## 목록의 지연 배치를 잃지 말 것

히어로를 화면 끝까지 붙이려고 `PageShell` 의 자식을 `Column` 하나로 묶었더니 **목록이 지연
배치를 잃었다.** 홈은 가로 열이 열두 개라 화면 밖 열까지 전부 배치된다. 자식마다 여백을 주는
방식(`_Gutter`)으로 바꿔 목록 구조를 유지했다.

## 쓰다 만 후기는 기록 탭으로

홈에서 기록 탭으로 옮겼다. 다만 **복구 상태 기계는 홈에 그대로 뒀다** — 초안이 있으면 조리
이어하기를 숨기는 경합 처리가 거기 있고, 테스트 열다섯 건이 그걸 지킨다. 그리는 위치만 옮겼다.

테스트는 초안 존재를 "후기 카드가 보이는가" 로 관찰하고 있었다. 카드가 홈에서 사라졌으므로
**"조리 카드가 안 뜨는가" 로 바꿨고, 활성 세션을 함께 주도록 고쳤다.** 세션이 없으면 단정이
항상 참이라 아무것도 검증하지 못한다.

## 헤더 로고의 김과 `pumpAndSettle`

검색·기록·내 정보 헤더의 냄비에서 김이 계속 오른다. 끝없이 반복하는 애니메이션이 화면에
상주하므로 **`pumpAndSettle` 이 영원히 끝나지 않는다.** `test/flutter_test_config.dart` 에서
테스트 전역으로 모션을 꺼서 해결했다. 새 화면에 상시 애니메이션을 넣을 때 같은 문제가 난다.

## iOS 실기기

- **디버그 빌드는 홈 화면에서 누르면 반드시 튕긴다.** iOS 가 디버거 없이 JIT 을 막는데 Flutter
  디버그는 JIT 이다. 실기기 배포는 `--release` 여야 한다.
- **평문 HTTP.** 베타 서버가 `http://13.209.243.235` 다. `NSAllowsArbitraryLoads` 로 전체를
  여는 대신 그 호스트만 `NSExceptionDomains` 예외로 뒀다. **서버에 HTTPS 를 붙이면 지운다.**
- **카카오 로그인이 iOS 에서 설정된 적이 없었다.** 안드로이드만 매니페스트에 스킴이 있었다.
  `CFBundleURLTypes`(`kakao{네이티브앱키}`)와 `LSApplicationQueriesSchemes` 를 넣었다.
  **남은 일: 카카오 콘솔에 iOS 플랫폼 번들 ID `com.cookpilot.cookpilot` 등록.** 안드로이드는
  키 해시로, iOS 는 번들 ID 로 검증한다.
- `ios/Podfile.lock` 이 `google_sign_in` 추가 이전 상태로 멈춰 있었다. `pod install` 결과를
  함께 커밋한다.

## 이 PR 에 아직 없는 것

- **내 정보 화면.** 시안의 그룹형 설정 목록(화면 / 내 취향 / 앱)으로 아직 안 바꿨다.
- **검색창 통합.** 요리 이름과 재료를 한 칸으로 합치려면 백엔드가 둘을 **OR** 로 묶어야 한다.
  지금은 AND 라 같은 말을 두 파라미터에 넣으면 결과가 오히려 준다(두부 159 → 87).
  운영 데이터로 재 보면 이름으로만 걸리는 레시피는 감자·새우 0건, 두부 2건뿐이라 합칠 값어치가
  있다. 다만 김치는 이름 전용이 26건이라 OR 이 꼭 필요하다.
- **카드 지표(조회수·저장수·조리시간).** 표본 20건 중 단계 타이머가 있는 레시피가 0건이고,
  조회수는 유튜브 기반에만 들어온다. 저장수는 `recipe_favorites` 집계를 요약 응답에 실어야 한다.
