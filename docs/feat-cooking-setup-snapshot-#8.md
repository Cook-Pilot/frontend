# #8 F-02 조리 전 설정과 실행 스냅샷

## 목적

조리를 시작하기 전에 이번 조리에 사용할 레시피 버전, 인분, 재료 변경을
확정한다. 시작 이후에는 서버의 원본 레시피나 개인 버전이 바뀌더라도 현재
조리가 영향을 받지 않도록 최종 설정을 로컬 실행 스냅샷으로 저장한다.

## 조리 전 설정

- 기본 레시피와 최신 개인 레시피 버전 중 하나를 선택한다.
- 개인 버전이 있으면 상세 API를 호출해 합성된 재료와 조리 단계를 불러오고
  기본 선택으로 사용한다.
- 개인 버전 로딩 실패 또는 조리 단계 누락 시 기본 레시피로 안전하게
  되돌아간다.
- 인분을 변경하면 현재 화면의 모든 수량형 재료를 같은 비율로 조정한다.
- 재료별로 양 조절, 직접 입력 대체, 생략을 지원한다.
- 대체 재료의 양은 계속 조절할 수 있으며, 별도 버튼으로 기본 재료에
  되돌릴 수 있다.
- 필수 재료 생략은 막지 않지만 조리 결과가 달라질 수 있음을 경고한다.

인분 환산식은 다음과 같다.

`변경 수량 = 현재 수량 × 변경 인분 ÷ 현재 인분`

사용자가 직접 조절한 재료도 이후 인분 변경 시 같은 비율로 확대·축소된다.

## 개인 레시피 API

`GET /api/v1/personal-versions/{versionId}`를 호출해 서버가 합성한 개인 버전
상세를 읽는다.

프론트는 JPA Entity나 원본 조정 테이블을 직접 다루지 않고 다음 실행값만
사용한다.

- 개인 버전 ID, 제목, 요약
- 합성된 재료 이름·양·단위·필수 여부
- 합성된 조리 단계·타이머·주의 문구

## 실행 스냅샷

`CookingSetupSnapshot`은 조리 시작 버튼을 누르는 순간 다음 값을 고정한다.

- 원본 레시피 ID와 화면 표시 정보
- 기본 인분과 이번 조리 인분
- 기본/개인 버전 출처와 개인 버전 ID
- 최종 재료 이름·양·단위·대체·생략 상태
- 최종 조리 단계와 타이머

생략한 재료는 실제 `CookSessionScreen`에 전달하는 실행 레시피에서 제외한다.
스냅샷 자체에는 생략 사실을 남겨 이후 후기·개인 레시피 저장 기능이 활용할
수 있게 한다.

`toExecutionRecipe()`는 이미 이번 인분에 맞춰 계산된 수량을 조리 화면이
사용할 수 있도록 변환한다. 카탈로그 레시피의 개인 버전 보유 여부를 복제하는
함수가 아니므로, 개인 버전 메타데이터는 실행 레시피에 넣지 않는다.

## 기존 조리 세션 저장과의 관계

`PersistedCookingSession`은 메인에 원래 있던 프론트 로컬 저장 클래스이며
DB 테이블이 아니다. 기존 단계·타이머 복원 데이터에 선택적인
`setupSnapshot` 필드만 추가했다.

- 새 세션: 실행 스냅샷을 함께 저장하고, 이어하기 시 서버 조회 없이 동일한
  재료와 단계로 복원한다.
- 기존 세션: 스냅샷이 없으면 기존 방식대로 레시피 API를 조회해 복원한다.
- 저장 키 `cookpilot.active_cooking_session.v1`은 유지한다. 새 필드가
  선택적이라 기존 JSON과 양방향 호환되기 때문이다.
- 실행 스냅샷에는 별도 `schemaVersion`을 기록한다. 버전 필드가 없는 기존
  저장값은 계속 읽고, 앱이 해석할 수 없는 미래 버전은 설정만 제외한다.
- 설정만 손상된 경우 진행 단계와 타이머까지 삭제하지 않는다. `recipeId`
  기반 기본 레시피 복원으로 안전하게 낮춰서 이어간다.
- 잘못된 기준 인분은 1인분으로 보정하고, 대체 재료를 기본 재료로 되돌릴
  때는 이름뿐 아니라 현재 인분의 원래 기준량도 함께 복원한다.

## 대체재 추천 범위

이번 이슈에서는 사용자가 대체 재료 이름을 직접 입력한다. 임의의 고정 추천은
안전성, 맛, 조리법 맥락을 보장할 수 없어 넣지 않았다.

재료 정규화, 대체 가능 관계, 알레르기·조리법 조건을 포함하는 서버 대체재
카탈로그는 별도 백엔드 설계와 Discussion에서 다룬다.
