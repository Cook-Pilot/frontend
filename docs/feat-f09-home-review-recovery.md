# F9 홈 후기 복구

## 목적

조리 완료 뒤 후기를 저장하기 전에 앱이 종료돼도 홈에서 작성 중인 후기로
돌아갈 수 있게 한다. 홈은 `PendingReviewDraftStore`를 먼저 확인하고, 초안이
없을 때만 진행 중 조리 세션을 복원한다.

## 홈 표시 우선순위

1. 복구 데이터 로딩
2. 로드 오류와 `다시 시도`
3. 작성 중 후기의 `후기 작성 이어가기`
4. 진행 중 조리의 `이어서 요리하기`
5. 복구 카드 없음

후기 초안과 활성 조리 세션이 동시에 남아 있으면 후기 카드만 표시한다. 조리
완료 이후의 후기 작성이 이미 시작된 상태에서 이전 조리 화면으로 되돌아가는
경로를 만들지 않기 위해서다.

## 복구 동작

- 후기 카드는 저장된 `PendingReviewDraft` 객체를 그대로
  `ReviewScreen(initialDraft: draft)`에 전달한다.
- 카드 연타는 첫 화면 전환이 끝날 때까지 무시한다. 같은 초안으로 후기 화면이
  여러 장 열리고 뒤쪽 화면의 dispose 저장이 완료된 초안을 되살리는 것을 막는다.
- 후기 화면에서 홈으로 돌아오면 저장소를 다시 읽는다. 후기가 저장돼 초안이
  정리됐다면 카드도 즉시 사라진다.
- 레시피 카탈로그 오류의 재시도와 pull-to-refresh는 카탈로그뿐 아니라
  후기/조리 복구 상태도 함께 새로 읽는다. 복구 오류 카드의 `다시 시도`는
  카탈로그를 건드리지 않고 복구 상태만 다시 확인한다.
- 로드 실패는 초안이 없는 것으로 간주하지 않는다. 오류 카드를 표시하고 활성
  조리 카드도 숨겨, 확인되지 않은 상태에서 잘못된 복구 경로를 노출하지 않는다.
- 각 복구 요청에는 증가하는 generation을 부여한다. 이전 요청이 늦게 끝나도
  더 최신 요청이 만든 화면 상태를 덮어쓰지 못한다.
- 홈 복구는 활성 조리 저장소를 읽기만 한다. 오래된 비동기 레시피 조회가 끝난
  뒤 새로 시작한 조리 세션을 지우거나 예전 값으로 덮지 않도록, 404·빈 단계
  같은 복구 불가 값도 홈에서 직접 clear/save하지 않는다.
- 활성 조리 세션과 레시피 조회가 끝난 뒤 후기 초안을 한 번 더 읽는다. 첫
  조회 이후 새 초안이 생겨도 활성 조리보다 후기를 우선 표시한다. 활성 조회가
  실패해도 재확인을 건너뛰지 않고, 새 초안이 없을 때만 해당 오류를 표시한다.
- 실제 조리 저장소 초기화 오류는 빈 세션으로 바꾸지 않고 홈의 복구 오류로
  전달한다.
- `setState`에는 동기 상태 변경만 넣고 저장소·API 작업은 밖에서 기다린다.

## 새 조리 진입 보호

`PendingReviewDraftStore`는 작성 중 후기 한 건과 서버가 수락한
`acceptedReviewId`를 함께 보관한다. 이 값이 남은 동안 다른 조리를 완료하면
singleton 초안을 덮어써 안전한 재시도 기준을 잃을 수 있으므로, 새 조리보다
기존 후기 완료를 우선한다.

- Home의 오늘 메뉴·최근·즐겨찾기·전체 목록과 Search 결과는 모두
  `RecipeDetailScreen`을 거쳐 `CookSetupScreen`으로 수렴한다. 실제
  `CookSessionScreen`을 열기 직전에 pending draft를 다시 읽고, 초안이 있으면
  새 조리를 열지 않고 같은 draft의 `ReviewScreen`으로 이동한다.
- 후기 화면 뒤에 남은 기존 조리 설정 화면에서도 같은 최종 guard를 거치므로
  시스템 뒤로가기 후 새 세션을 시작해 초안을 덮는 우회 경로가 없다.
- Home의 `이어서 요리하기`도 저장된 화면 상태만 신뢰하지 않고 탭 직전에
  pending draft를 다시 읽는다. 그 사이 초안이 생겼으면 후기 화면을 우선 연다.
- pending 저장소 조회 실패는 `초안 없음`으로 간주하지 않는다. 새 조리와 조리
  재개를 모두 fail-closed하고 재시도 안내를 표시한다.
- 조회 중에는 진입 버튼을 잠가 중복 탭이 여러 조리·후기 route를 만들지 않게
  한다. pending draft가 없을 때는 기존 조리 설정·재개 동작을 유지한다.

## 스택 의존성

이 복구 진입점은 같은 PR에서 `ReviewScreen`이
`required PendingReviewDraft initialDraft`를 받는 후기-flow 계약과 함께
제공한다. 따라서 후기 화면을 뒤로 닫거나 앱을 다시 열어도 Home에서 저장된
초안을 다시 열 수 있다. 같은 PR의 단일 진입 guard가 이 기본 도달성 위에서
카드 연타로 후기 화면이 중복으로 열리는 경로도 차단한다.

## 검증 범위

위젯 테스트는 다음을 고정한다.

- 후기 초안 표시
- 후기와 활성 조리 세션 동시 존재 시 후기만 표시
- 활성 세션 조회 중 생긴 새 후기 초안 우선 표시
- 후기 초안이 없을 때 활성 조리 세션 표시
- 카드 탭 시 동일한 초안과 입력값 전달
- 카드 연타 시 후기 화면 단일 진입
- 후기 화면 복귀 시 재조회
- 후기·조리 저장소 로드 오류 시 활성 세션 은닉 및 재시도
- 실제 조리 저장소 초기화 오류 전달
- 늦게 끝난 이전 복구 요청이 최신 결과를 덮지 않음
- 늦게 끝난 두 번째 초안 조회도 최신 결과를 덮지 않음
- pull-to-refresh로 카탈로그와 새 초안을 함께 갱신
- 조리 설정에서 pending 없음·있음·조회 오류·중복 탭에 따른 조리/후기 route
  경계
- Home 조리 재개 직전 새 pending draft와 조회 오류의 fail-closed 처리
