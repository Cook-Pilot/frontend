# F9 홈 후기 복구

## 목적

조리 완료 뒤 후기를 저장하기 전에 앱이 종료돼도 홈에서 작성 중인 후기로
돌아갈 수 있게 한다. 홈은 `PendingReviewDraftStore`를 먼저 확인하고, 초안이
없을 때만 진행 중 조리 세션을 복원한다.

## 홈 표시 우선순위

1. 복구 데이터 로딩
2. 로드 오류와 `다시 시도`
3. 작성 중 후기의 `후기 작성 이어가기`
4. 진행 중 조리의 `이어서 요리하기`
5. 복구 카드 없음

후기 초안과 활성 조리 세션이 동시에 남아 있으면 후기 카드만 표시한다. 조리
완료 이후의 후기 작성이 이미 시작된 상태에서 이전 조리 화면으로 되돌아가는
경로를 만들지 않기 위해서다.

## 복구 동작

- 후기 카드는 저장된 `PendingReviewDraft` 객체를 그대로
  `ReviewScreen(initialDraft: draft)`에 전달한다.
- 후기 화면에서 홈으로 돌아오면 저장소를 다시 읽는다. 후기가 저장돼 초안이
  정리됐다면 카드도 즉시 사라진다.
- 레시피 카탈로그 오류의 재시도와 pull-to-refresh는 카탈로그뿐 아니라
  후기/조리 복구 상태도 함께 새로 읽는다. 복구 오류 카드의 `다시 시도`는
  카탈로그를 건드리지 않고 복구 상태만 다시 확인한다.
- 로드 실패는 초안이 없는 것으로 간주하지 않는다. 오류 카드를 표시하고 활성
  조리 카드도 숨겨, 확인되지 않은 상태에서 잘못된 복구 경로를 노출하지 않는다.
- 각 복구 요청에는 증가하는 generation을 부여한다. 이전 요청이 늦게 끝나도
  더 최신 요청이 만든 화면 상태를 덮어쓰지 못한다.
- 홈 복구는 활성 조리 저장소를 읽기만 한다. 오래된 비동기 레시피 조회가 끝난
  뒤 새로 시작한 조리 세션을 지우거나 예전 값으로 덮지 않도록, 404·빈 단계
  같은 복구 불가 값도 홈에서 직접 clear/save하지 않는다.
- `setState`에는 동기 상태 변경만 넣고 저장소·API 작업은 밖에서 기다린다.

## 스택 의존성

이 복구 진입점은 같은 PR에서 `ReviewScreen`이
`required PendingReviewDraft initialDraft`를 받는 후기-flow 계약과 함께
제공한다. 따라서 후기 화면을 뒤로 닫거나 앱을 다시 열어도 Home에서 저장된
초안을 다시 열 수 있다. 후속 PR은 이 기본 도달성 위에서 카드 연타와 active
조회 중 새 초안 경합, 실제 저장소 초기화 오류 전달을 보강한다.

## 검증 범위

위젯 테스트는 다음을 고정한다.

- 후기 초안 표시
- 후기와 활성 조리 세션 동시 존재 시 후기만 표시
- 후기 초안이 없을 때 활성 조리 세션 표시
- 카드 탭 시 동일한 초안과 입력값 전달
- 후기 화면 복귀 시 재조회
- 후기·조리 저장소 로드 오류 시 활성 세션 은닉 및 재시도
- 늦게 끝난 이전 복구 요청이 최신 결과를 덮지 않음
- pull-to-refresh로 카탈로그와 새 초안을 함께 갱신
