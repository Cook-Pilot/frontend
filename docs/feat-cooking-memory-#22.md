# F-10 조리 기록 및 개인 레시피 버전

## 구현 범위

- 조리 설정 화면에서 원본과 최근 개인 버전 최대 5개를 보여준다.
- 개인 버전은 자동 적용하지 않고 사용자가 `기본`, `vN` 중 직접 선택한다.
- 조리 시작 시 확정한 재료·단계와 원본 항목 ID를 실행 스냅샷에 보관한다.
- 인분 변경, 재료 양 조절·대체·생략, 조리 중 타이머 변경을 후기 요청에 포함한다.
- 별점, 이번 조리 메모, 다음 조리 메모를 서버에 저장한다.
- 개인 메모리 탭에서 월별 달력과 날짜별 조리 기록을 보여준다.

## 화면 흐름

```text
레시피 상세
→ 조리 설정에서 기본 또는 vN 선택
→ 인분·재료 설정 확정
→ 조리 중 타이머 변경 기록
→ 조리 완료
→ 별점·메모와 실제 실행 스냅샷 저장
→ 개인 메모리 달력에서 다시 확인
```

## 조리 세션 식별

조리를 시작할 때 클라이언트 UUID를 하나 생성한다. 진행 중 세션을 복원해도 같은 UUID를 유지하고, 후기 저장을 다시 눌러도 같은 값을 전송한다.

백엔드는 이 값을 사용자 ID와 함께 중복 저장 방지 키로 사용한다. 응답이 늦거나 네트워크 재시도로 같은 요청이 다시 전송돼도 후기와 개인 버전이 중복 생성되지 않는다.

## 실행 스냅샷

`CookingSetupSnapshot`은 조리 시작 시점에 다음 값을 고정한다.

- 원본 레시피 ID와 선택한 개인 버전 ID
- 기준 인분과 실행 인분
- 재료의 원본 ID, 실제 이름·양·단위, 생략 여부
- 단계의 원본 ID, 설명과 기본 타이머

`PersistedCookingSession`에는 세션 UUID와 단계별 변경 타이머도 함께 저장한다. 앱을 종료했다가 복원해도 완료 요청이 같은 조리 결과를 가리키게 하기 위해서다.

## 후기 저장

`POST /api/v1/reviews`

- 후기는 실제 변경 여부와 무관하게 항상 저장한다.
- `createdPersonalVersionId`가 있으면 이번 변경으로 새 `vN`이 만들어진 것이다.
- 값이 없으면 별점·메모와 조리 이력만 저장된 것이다.
- 저장이 실패하면 같은 화면에서 재시도하며 동일 세션 UUID를 재사용한다.

## 개인 메모리 달력

`GET /api/v1/cooking-history?from=<ISO-8601>&to=<ISO-8601>`

- 화면에 표시 중인 월의 시작 이상, 다음 달 시작 미만 범위를 조회한다.
- 별도 달력 테이블 없이 서버 이력을 날짜별로 묶는다.
- 날짜를 선택하면 그날 조리한 요리, 별점, 메모와 생성된 개인 버전을 표시한다.
- 요리 항목을 누르면 같은 달에 먹은 동일 레시피 기록도 함께 확인할 수 있다.

## MVP 제외

- 원본 레시피 자동 수정
- 최신 개인 버전 자동 적용
- 사진 업로드
- 음성 원문 저장과 LLM 변경 추출
- 다른 요리로 취향 확장
- 대체 재료 추천 카탈로그

## 검증

- 사용자 세션이 없으면 개인화 HTTP 요청을 보내지 않는다.
- 최근 버전을 명시적으로 선택한 뒤에만 설정에 적용한다.
- 세션 UUID와 변경 타이머가 앱 재실행용 저장소에 남는다.
- 후기 요청에 실제 재료·단계와 원본 ID가 포함된다.
- 조리 기록 응답의 타입이 잘못되면 일관된 API 오류로 처리한다.
- 기존 화면·조리 세션 테스트를 포함한 전체 Flutter 테스트가 통과한다.
