# fix/cook-appbar-pause-button-#44 — 의미 없는 버튼 제거와 후기 저장 후 홈 자동 이동

이슈 #44는 실사용에서 발견한 두 가지 불편을 함께 다룬다.

1. 조리 중 화면에 아무 동작도 하지 않는 버튼이 있다.
2. 후기를 저장한 뒤 "홈으로" 버튼을 한 번 더 눌러야 홈으로 간다. 그 버튼이 스크롤해야 보인다.

---

## 1. 조리 중 화면 앱바의 동작 없는 일시정지 버튼

### 문제 상황

조리 중 화면(`CookSessionScreen`) 앱바 우측에 일시정지 아이콘 버튼이 있었지만
`onPressed`가 빈 콜백이라 눌러도 아무 일도 일어나지 않았다.

```dart
actions: [
  IconButton(
    onPressed: _completionLocked ? null : () {},
    icon: const Icon(Icons.pause_rounded),
  ),
],
```

동작하는 부분은 `_completionLocked`(완료 저장 중)일 때 비활성화되는 것뿐이었다.
UI 목업 단계에서 자리만 잡아둔 placeholder가 그대로 남은 것으로,
F-09 작업(`e7ec50f`)에서 잠금 조건만 덧붙었을 뿐 기능은 채워진 적이 없다.

사용자에게는 정지 버튼처럼 보여서 "조리를 멈추는 버튼"으로 오해를 준다.

### 검토한 대안

| 대안 | 판단 |
| --- | --- |
| 버튼 제거 | **채택.** 아래 참고 |
| 타이머 일시정지에 연결 | 본문 타이머 버튼(`_toggleTimer`)과 기능이 완전히 중복된다 |
| 세션 일시정지 기능 신규 구현 | `docs/`에 해당 기능 명세가 없다. 명세 없는 기능을 임의로 만들지 않는다 |

앱바가 담당해야 할 동작은 이미 다른 곳에 있다.

- **타이머 일시정지/재개** → 본문 타이머 카드 버튼(`_toggleTimer`). 상태에 따라
  `타이머 시작` / `일시정지` / `계속` 라벨로 바뀐다.
- **조리 세션 중단** → 앱바 좌측 나가기(`Icons.close_rounded`, `_closeCookingSession`).

즉 앱바 우측 버튼이 맡을 고유한 역할이 없으므로 제거가 가장 작은 변경이다.

### 최종 결정

`CookSessionScreen`의 `AppBar.actions`를 통째로 삭제했다. 앱바에는 나가기 버튼과
제목(레시피명 · 인분)만 남는다. `_completionLocked`는 다른 곳에서 계속 쓰이므로 그대로 둔다.

## 2. 후기 저장 뒤 홈 자동 이동

### 문제 상황

`ReviewScreen`은 저장에 성공하면 화면에 결과 InfoStrip을 띄우고, 하단 버튼 라벨을
`조리 기록 저장` → `홈으로`로 바꿨다. 홈에 가려면 저장 후 같은 버튼을 한 번 더 눌러야 한다.

후기 화면은 별점·후기·다음 메모·개인 버전 스위치가 이어진 긴 스크롤이라
저장을 마친 시점에는 하단 버튼이 화면 밖인 경우가 많다. 저장은 끝났는데
"왜 안 넘어가지" 하고 스크롤을 내려야 하는 흐름이다.

### 최종 결정

저장에 **성공**하면 곧바로 홈으로 이동하고, 결과는 하단 스낵바로만 알린다.

- `_save()` 성공 분기에서 `ScaffoldMessenger`를 먼저 캡처하고 `_goHome()` 뒤에
  `showSnackBar`를 호출한다. 스낵바는 루트 `ScaffoldMessenger`가 띄우므로
  `pushAndRemoveUntil`로 화면을 갈아끼워도 살아남는다.
- 스낵바 문구는 기존 `_successMessage`를 그대로 쓴다(`후기만 저장했어요.` /
  `후기와 개인 버전을 저장했어요.` 등). 결과별 안내를 잃지 않기 위해서다.
- 정리(clear) 실패 경고는 화면 InfoStrip 대신 같은 스낵바 뒤에 이어 붙인다.
  정리 실패는 저장 실패가 아니므로 홈 이동을 막지 않는다.
- 도달할 수 없게 된 UI를 함께 지웠다 — 성공 InfoStrip 두 개, 하단 버튼의 `_goHome`
  분기와 `홈으로` 라벨, 그리고 `_cleanupWarning` 필드(`_save()` 지역 변수로 대체).

**실패 경로는 바꾸지 않았다.** 후기 API 실패, 개인 버전 승인 실패, 후기 ID checkpoint
실패는 전부 화면에 남아 같은 자리에서 재시도한다. 홈으로 보내는 건 성공했을 때뿐이다.

### `homeBuilder` 주입점

`ReviewScreen`에 `WidgetBuilder? homeBuilder`를 추가했다(기본값 `MainShell`).
실제 홈은 레시피 로딩 스피너가 계속 도는 탓에 위젯 테스트에서 `pumpAndSettle`이
끝나지 않는다. 이 화면이 이제 항상 홈으로 이동하므로 테스트에서 홈을 대체할 수단이 필요했다.
`alarm`, `advicePort`, `recipeRepository` 등 기존 테스트 주입 관례를 그대로 따랐다.

한 테스트에서 실제 `MainShell`을 띄우면 그 다음 테스트의 `pumpAndSettle`까지 함께 느려져
저장이 끝나기 전에 검증이 실행됐다. 저장까지 진행하는 테스트에는 빠짐없이 `homeBuilder`를 넘긴다.

## 검증

- `test/features/mvp/cook_session_app_bar_test.dart` 신규 — 앱바에 나가기 버튼이 있고
  일시정지 아이콘은 없음을 확인한다. 수정 전 코드에서는 실패하는 것을 확인했다.
- `test/features/mvp/review_flow_test.dart` — `저장에 성공하면 버튼을 더 누르지 않아도
  홈으로 이동하고 결과를 스낵바로 알린다` 신규. `ReviewScreen`이 트리에서 사라지는 것까지 본다.
  기존 저장 성공 테스트들의 검증 대상은 화면 InfoStrip에서 홈 도달 + 스낵바로 옮겼고,
  정리 실패 테스트는 경고가 스낵바 안에 들어갔는지 확인한다.
- `dart format .`, `flutter analyze`, `flutter test` 통과.

## 이후 작업에서 지킬 것

- 앱바에 동작 없는 placeholder 버튼을 다시 두지 않는다. 위 테스트가 회귀를 막는다.
- 세션 일시정지가 실제로 필요해지면 먼저 `docs/`에 명세를 남기고,
  타이머 일시정지와 역할이 어떻게 다른지 정한 뒤 구현한다.
- 후기 화면에 저장 성공 상태를 다시 만들지 않는다. 성공은 홈 이동 + 스낵바로 끝이고,
  화면에 남는 안내는 재시도가 필요한 실패 상태뿐이다.
- 저장까지 진행하는 `ReviewScreen` 테스트에는 항상 `homeBuilder`로 가짜 홈을 넘긴다.
  실제 홈을 띄우면 그 테스트뿐 아니라 뒤따르는 테스트까지 불안정해진다.
