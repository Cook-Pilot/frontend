# #14 홈 최근 조리·즐겨찾기 연동

## 목적

홈 화면의 최근 조리와 즐겨찾기를 목데이터 대신 현재 익명 베타 사용자의
실제 서버 데이터로 표시한다.

## API

| Method | URL | 역할 |
| --- | --- | --- |
| `GET` | `/api/v1/home/recent-recipes` | 최근 조리 레시피 조회 |
| `GET` | `/api/v1/favorites` | 즐겨찾기 목록 조회 |
| `PUT` | `/api/v1/recipes/{recipeId}/favorite` | 즐겨찾기 등록 |
| `DELETE` | `/api/v1/recipes/{recipeId}/favorite` | 즐겨찾기 해제 |

모든 요청에 `BetaUserSession.requestHeaders`를 사용해
`X-CookPilot-User-Id`를 전달한다.

## 홈 데이터 구성

홈 진입 시 레시피 목록, 최근 조리, 즐겨찾기를 조회하고 `_HomeCatalog`로 묶는다.
각 목록은 화면에서 필요한 `RecipeSummary`만 사용하며 JPA Entity나 API 원본 JSON을 노출하지 않는다.

- 오늘의 메뉴: 전체 레시피 중 표시 가능한 첫 항목
- 최근 조리: 서버가 반환한 최신 조리 레시피
- 즐겨찾기: 현재 사용자가 저장한 레시피
- 전체 레시피: DB 카탈로그 전체

## 빈 상태와 오류

신규 사용자는 최근 조리와 즐겨찾기가 없으므로 빈 목록을 정상 응답으로 처리한다.

- 최근 조리 없음: 첫 요리와 후기 저장을 안내
- 즐겨찾기 없음: 상세 화면에서 저장하도록 안내
- 전체 레시피 없음: 등록된 레시피가 없다는 안내
- API 실패: 다시 시도 버튼으로 홈 데이터를 새로 조회

## 즐겨찾기 동작

레시피 카드를 선택해 상세 화면으로 이동한 뒤 상단 북마크 버튼으로 등록·해제한다.
처리 중에는 중복 요청을 막고, 성공 후 화면 상태를 변경한다.
상세에서 홈으로 돌아오면 홈 데이터를 다시 불러와 목록과 북마크 상태를 맞춘다.

PUT과 DELETE는 같은 요청을 반복해도 최종 상태가 유지되는 서버 API를 사용한다.

## 데이터 기준

- 최근 조리는 서버의 `post_cook_reviews.created_at` 최신순 결과를 사용한다.
- 한 사용자가 같은 레시피를 여러 번 조리해도 홈에는 레시피가 중복되지 않는다.
- 홈에서는 최근 조리와 즐겨찾기를 각각 최대 3개만 먼저 보여준다.
- 즐겨찾기는 사용자별 `recipe_favorites` 상태를 기준으로 표시한다.
- 신규 익명 사용자는 두 목록이 빈 상태로 시작하며, 이는 오류가 아니다.
- 상세 화면에서 즐겨찾기를 바꾸거나 조리를 진행하고 돌아오면 레시피 목록,
  최근 조리, 즐겨찾기와 로컬 조리 이어하기 상태를 함께 새로 조회한다.

최근 조리 데이터의 생성 자체는 후기 저장 API의 책임이다. 이 이슈는 이미 저장된
최근 조리 결과를 홈에서 조회·표시하는 범위와 즐겨찾기 등록·해제를 담당한다.
